# nom2.jp 日本酒一覧（sakeカタログ）更新ルーティーン

nom2.jpの`/nihonshu`ページは、MicroCMSの`sake`エンドポイントのデータを表示している。既存320件は2026年4月に楽天商品データから一括インポートされたきり更新が止まっている。このスキルは、楽天市場から新しい日本酒商品を探し、**銘柄名・蔵元名を整形した上で**新規登録することで、このカタログを継続的に増やす。

sake-article-routine（記事執筆）とは別物。こちらは短い構造化データの登録のみを行う。

## sakeエンドポイントのフィールド
| フィールドID | 内容 |
|---|---|
| `name` | 商品名（楽天の元タイトルから、送料無料・ギフト等の販促文言を除いたクリーンな名前） |
| `brewery` | 蔵元名（分かる場合のみ。自分の知識で特定できなければ空欄のままでよい。不確かな推測はしない） |
| `brand` | 銘柄名（例: 獺祭、久保田、新政など） |
| `price` | 価格（楽天の`itemPrice`） |
| `description` | 1〜2文の簡潔な説明（広告文をそのまま転記しない） |
| `imageUrl` | 楽天の商品画像URL（`mediumImageUrls`等） |
| `purchaseUrl` | 楽天アフィリエイトURL（`affiliateUrl`） |

**注意**: TypeScript側の型定義には`prefecture`フィールドがあるが、**実際のMicroCMSスキーマには存在しない**（送信するとエラーになる）。都道府県情報が分かる場合は`prefecture`キーを送らず、`description`文中に含める。

## 手順

### 1. 既存カタログの取得（重複チェック用）
```js
import { listExistingSake } from "./lib/sakeCatalog.mjs";
const existing = await listExistingSake();
```
`existing`の`name`・`brand`・`purchaseUrl`を使って、これから登録する候補が既存と重複していないか確認する。

### 2. 楽天から候補を検索
`lib/rakuten.mjs`の`searchItems(keyword, hits)`で日本酒商品を検索する。キーワードは「日本酒」だけでなく、多様性が出るよう都道府県名・特定名称（純米大吟醸、純米吟醸等）・季節（夏酒、ひやおろし等）を絡めてローテーションさせる。

```js
import { searchItems } from "./lib/rakuten.mjs";
const items = await searchItems("日本酒 純米大吟醸", 30);
```

手順1の`existing`と照合し（`purchaseUrl`の一致、または`brand`+価格帯の近さで判断）、まだ登録されていない候補を**10件程度**選ぶ。

### 3. 銘柄ごとにクリーンなデータへ整形
候補ごとに、楽天の生データ（`itemName`相当）から以下を生成する：
- `name`: 送料無料・ギフト訴求・日付限定セール文言等の販促ノイズを取り除いた商品名
- `brand`: 商品名から銘柄名を抽出
- `brewery`: 自分の知識で特定できる場合のみ記入。**分からない場合は空欄のままにする（不確かな推測で埋めない）**
- `description`: 詳細ページの説明欄がこれ1つしかないため、**1〜2文の一般論では情報量が薄すぎる**。広告文の丸写しはせず、以下のような具体的な要素を分かる範囲でできるだけ盛り込み、3〜5文程度にする：
  - 使用米・精米歩合・日本酒度・酸度など、楽天商品説明文やタイトルに記載があれば拾う
  - 味わいの特徴（辛口/甘口、香りの系統など）
  - 蔵元・産地の特徴（分かる場合。知らない蔵元について不確かな情報を書かない）
  - おすすめの飲み方・温度帯、合う料理など
  - 都道府県が分かれば文中に含める
  - 楽天の商品説明に十分な情報がなく埋められない場合は、無理に水増しせず分かる事実だけで簡潔にまとめる（不確かな情報を作らない）

### 4. MicroCMSへ登録（即公開）
```js
import { createSake } from "./lib/sakeCatalog.mjs";
const id = await createSake({ name, brewery, brand, price, description, imageUrl, purchaseUrl });
```
既存カタログと同じ運用に合わせ、下書きを挟まず即座に公開する。

### 5. 完了報告
ユーザーに以下を伝える：
- 今回登録した件数と、追加した銘柄名の一覧（簡潔に）
- 蔵元が特定できず空欄のまま登録した銘柄があれば、その旨
- 楽天APIの検索が失敗した場合はその旨（この場合は登録0件で終了してよい。無理に埋めない）
